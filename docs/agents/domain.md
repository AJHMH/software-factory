# Domain docs

This repository uses a single-context layout.

Before exploring, read root CONTEXT.md when present and relevant
architecture decisions in docs/adrs/. Preserve this existing ADR location.

If CONTEXT-MAP.md is introduced, follow its pointers to relevant contexts.
If context documents or ADRs are absent, proceed silently; create them
lazily when domain terms or decisions are resolved.

Use glossary vocabulary in specs, tickets, tests, and proposals.
Identify conflicts with existing ADRs explicitly.
